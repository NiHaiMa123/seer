## 一、可以直接用现成格子收的（不需新机制，按精灵逐只做）

这类是「规则表少认一种写法」或「异写没归一」，一条家族规则或一条文本归一即可闭合。
已用同样手法闭合 14 只（pet-3513 / 4901 / 3686 / 2909 / 3398 / 3637 / 3839 / 3668 / 2695
/ 3882 / 3965 / 4075 / 4248 / 4587）。

工作面：`no-rule` 883 片段、`no-trigger-prefix` 205 片段（合计约 1088 片段），
外加 `guard unmodeled` 417 / `prevApplied` 系 257 / `cond-orphan` 54 等 deferred 族。
`no-rule` + `no-trigger-prefix` 是**逐只处理的主战场**。

**找候选的加速器（本轮新增）**：不要一条条人工翻残文。先用
`node scratch/target-pick.mjs` 筛出「残文恰好 1 条且是 no-rule」的精灵（当前 68 只），
再用 `node scratch/near-rule.mjs` 给每条残文算出「最接近的现有规则 + LCS 覆盖率」，
按覆盖率降序看——覆盖率 ≥0.85 的基本就是「差一两个字」的词形缺口。
`node scratch/gap-list.mjs <minLen> <maxLen>` 可把全部 no-rule 片段去重后按长度列出，
用来扫某一长度的句式族。

手法（每只都要走完这四步，缺一不可）：
1. `node scratch/soulmark-residue.mjs --ids pet-XXXX` 看残文原句；
2. `node scratch/probe-clause.mjs "<子句>"` 看现有规则认不认（`PARSE_DEBUG=1` 打印命中规则 id）；
3. 改家族规则（`tools/effects-rules/*.mjs`）或文本归一（`condOf` 归一链）；
4. `node scratch/parse-snapshot.mjs` 出快照 → `parse-diff.mjs` 与上一步基线比，
   **必须 0 回归**；再 `node tools/sync-soulmarks.mjs --write pet-XXXX` 定点写回内容包。

已知的异写/别名清单（可直接照抄手法）：
- 「将/把」前缀（句中把字标记，句首剥除锚定 ^ 剥不掉）→ 规则要自己认（heal-184 已做）。
- 「固伤/固定伤害」是「伤害」的别称（e36-15 已做）。
- 「不出X状态」=「不处于X状态」（condOf 归一链已做）。
- 「附带N%令对手<异常>」=「N%令对手<异常>」（batch-e5-13b 已做）。
- 「攻击/所有攻击」作主语（常驻义）vs「下次攻击」（次数义）——两者语义不同，别混。
- 「伤害值 / 伤害量」同义（batch-e6-159 已收 `[值量]`）。
- 「能力提升状态 / 能力提升」同义（batch-e5c-04 已收可选「状态」后缀）。
- 「N%等量固伤」= 当次出伤的 N% 作固定伤害（batch-e6-159b 新增）。
- 「100%消除对手回合类效果和能力提升状态」= clear_stages(up) + cleanse(timed)
  （attach-damage-81 已收；clear_stages 没有 chance 参数，所以只收 100%）。
- 「自身最大体力**值**N%」与「自身最大体力N%」同义（e8-ft-11 已收「值」）。
- 「我方」= 自身（魂印语境持有者即行动方）——归一链用 `^(若?)我方` → `"$1自身"`，
  **原句有没有「若」就带不带**，不能写死替换串（见第六轮的坑）。
- 「出手后恢复…」「之后恢复…」的「后」是**词的一部分**，由 PART_PRE_STRIP 整词剥；
  残头剥字必须排在 PART_PRE_STRIP **之后**（见第六轮的坑）。
- **同义扩展必须落在原有那条规则上**，不能新起一条（见第七轮的坑）。
  「吸收」= 「吸取」（吸血语境）；「最大HP / 最大生命值」= 「最大体力」；
  「固伤」= 「固定伤害」；「几率」= 「概率」；「体」= 「体力」。
  但**护盾语义的「吸收伤害」不是吸血**，「能力提升状态**被**吸取」说的是状态被移除——
  这两类不能跟着一起放宽。

## 一之四、未建模条件的负载被**无条件执行**（第十轮修复，安全级）

第九轮分桶时发现一批「当前解析丢了条件」的条目，追下去发现其中一类是
**带未建模条件的负载变成了无条件执行**——不是效果缺失，是**行为错误**。

### 形状

pet-4814 娜诺：
「…自身微弱对手时，对手计算攻击伤害时的乘以克制倍数改为除以…；**自身克制对手时，战斗阶段结束时自身恢复所有技能2点PP值且反转对手能力提升状态**；…」

「自身克制对手时」「自身微弱对手时」都是**克制关系域未建模**的条件（attr-domain）。
解析器把它们留档后，**后面那个负载组却跑了出来，且丢了 `weCounterFoe` 条件**——
「战斗阶段结束时恢复所有技能2点PP值 + 反转对手能力提升」变成了**每回合末无条件执行**。

### 两个 bug

1. **组级**（`soulmark-parse.mjs` 的 quarantine 分支）：`condHold` 被消费时清掉了标记，
   但 `guardQuarantine` 仍为真 —— 于是**下一个未建模条件组**会通过「解除扣留」分支
   把扣留状态提前解除，负载随后被放行。
2. **clause 级**（`guardQuarantine && clause !== ""`）：只看 `startsWithSupportedTrigger`，
   没看 `condHold` —— 分号分隔的下一个 clause 会把扣留状态清掉。

### 修法

- 被扣下的组**不再改** `condHold`（扣留状态由 clause 边界收口）；
- clause 级检查加 `condHold` 分支：`condHold` 为真时**整个 clause 留档**，扣留到此结束。

**边界**：条件作用域的**精确**边界语法上不可判定（分号既可能是分隔也可能是同句延续），
这里按「clause 边界」近似。宁可多留残文（效果缺失且**有记录**），不可无条件执行（行为错误）。

**全库影响**：只有 pet-4814 一只，**0 回归**，moves 侧 0 变化。
内容包**不动** —— 包里的 `sm-4814` 带 `guard:{weCounterFoe:true}`，**包的版本更准**
（修复前的解析器才是错的）。修完解析器不再产出那个无条件效果，pet-4814 转入 fewer 桶。

**新立的一条纪律**：**宁可多留残文，不可无条件执行**。
「效果缺失且有残文记录」可以后续补；「无条件执行」是静默的行为错误，账面看不出问题。

## 一之五、第二类「无条件执行」：`cond-orphan`（**第十二轮已修**）

第十一轮扫 differ 桶时挖出一类**更隐蔽**的无条件执行 —— 它**连残文都不留**
（解析器声称解析成功，只是把条件扔了），所以审计台账完全看不出来。

### 形状

pet-3767 加梵迪：「…自身受到攻击伤害低于400则将伤害100%反弹给对手（…），**自身受到攻击伤害高于400则回合结束时恢复自身最大体力1/3**…」

- 内容包里（正确）：`onTurnEnd {heal 1/3}` + `guard:{prevDamageAboveAbs:400}`
- 当前解析（**错**）：`onTurnEnd {heal 1/3}` —— **条件没了**，每回合末无条件回血

### 根因（第十二轮定位到行号）

**不是**「条件属于哪一句」那族（Codex 两次撤回的那族），而是**句尾 boss 注记的作用域切分**：

1. `splitLocalBossScopes`（`tools/soulmark-parse.mjs`）遇到句尾「（boss无效）」时，
   会按**时序触发词**（`BOSS_SCOPE_TRIGGER_RE`：「回合结束时」「登场时」…）把这句话切开，
   让 boss 门只罩住**最近的那个独立时序片段**。
2. 原文「A，未触发则**回合结束时**B（boss无效）」里，切点正好落在「回合结束时」——
   于是「未触发则」被留在**前一段**，B 落进**后一段**。
3. 前一段以「未触发则」结尾 → 条件被暂存进 `pendingCond` 却无人消费 → 报 `cond-orphan`；
   后一段的 B **失去条件** → **无条件执行**。

复现最小（括号是唯一变量）：
- 「A，B」→ 条件保留 ✓
- 「A，B（boss无效）」→ 条件丢，残文 `cond-orphan` ✗

### 修法

作用域切分的锚点除已有的「若/当」守卫外，**再认结果分支标记**
（`未触发` / `未命中` / `触发成功` / `免疫成功` … +「则」）：
标记是负载的**前置作用域**，必须与它的负载同段。

### 结果（第十二轮实测）

- 全库解析快照 diff：**marks 1884 条里只变 13 条，moves 53780 条 0 变化** —— 0 回归。
- 12 只的无条件 else 负载被消掉（pet-3338 / 3358 / 3370 / 3487 / 3532 / 3634 / 3846 /
  3887 / 4009 / 4059 / 4081 / 4125），pet-3517 的 else 负载**带回了 `not prevApplied` 条件**。
- 残文账：`cond-orphan` **68 片段 / 65 条 → 57 片段 / 54 条**；
  同批 11 条转成 `prevApplied prerequisite — no same-event fallback host`（**更具体的诚实留档**）。
- 内容包定点同步 12 只（逐条语义复核，见下），装配 mounted 1596 → 1595
  （pet-3846 花清酒的唯一可建模效果就是那个无条件条目 → 魂印条目整体删除、不再挂载；
  它的正句「对手每次提升能力时触发效果」属**未建模的跨事件谓词**，仍留残文）。
- 新增回归测试 `tests/battle-core/parser/soulmark-boss-note-scope.test.ts`（5 项）。

### 关键判据：`not prevApplied` 只在**同一条目内**有效

引擎的 `prevApplied` 是**按条目重置**的（`packages/battle-core/src/ops/trigger.ts`：
`let prevApplied = false;` 在条目循环内）。所以：

| else 负载的位置 | `not prevApplied` 守卫 | 实际行为 |
|---|---|---|
| 与宿主**同一条目**（op 级 `if`） | 有效 | 条件成立才结算 ✓ |
| 另起一条目（条目级 `if`） | **恒真** | **等价于无条件执行** ✗ |

本轮同步的 12 只里，被删的正是「另起一条目」那一类；同条目内的那几条
（pet-3487 的 `crit_always`、pet-4059 的 `cleanse`）**保留不动**。

### 剩下的同类缺口（本轮未做，留待专门一轮）

- **`未触发则` 带时序的负载跨事件**：「未触发则回合结束时X」——负载在回合末，
  宿主在伤害结算/受击事件，IR 表达不了「记住上次没触发」。
  本轮一律**诚实留残文**（不再无条件执行）。
- **`not prevApplied` 跨条目不可观测**：pet-3517 霍夫曼的 else 负载仍挂在独立条目上，
  守卫形同虚设（内容包现状与之一致，本轮未动）。
  要真正生效，else 负载必须并进宿主条目（同条目内 `prevApplied` 链才有效）。
- **boss 注记的作用域宽度**：解析器把句尾「（boss无效）」只罩**最近时序片段**，
  内容包（如 pet-3517）把整句都罩住。两者**语义不等价**，但 `sync-soulmarks` 的
  `equiv` 桶按「hook|op|条件集合」判等价，**看不到 `bossGate` 差异** —— 这是分桶工具的盲区。
  本轮不动（改了会让怕敌人的 50% 失效能力在 boss 战重新生效）。

## 三、同一机制族的三处未解（下一轮最有价值的一块）

**族：条件作用域与分句归属。** 三处症状，同一个根——「条件属于哪一句」没有显式标记：

1. **「若P则A，且B」**：P 应同时罩 A 与 B；B（且续组）现在拿不到 P → 无条件执行。
   - 本轮两次尝试都被撤回。第一次（续组继承上一组守卫）**219 条变化、样本 8 条里 4 条是错的**
     （pet-4765/4799/4846 串味，pet-4834 语义反转）；第二次（把「且」切分的前半段另起一组）
     触发了「触发成功则…」分支的保护（soulmark-parse.test 的「不误伤并列子句」用例）。
   - 已确认的根因：作用域条件**未必在条目的 guard 里**——条件可能以**取反参数**形式存在
     （`passCondGate` / `negateBaseParam`：条件不成立时给宿主挂 `notSelfStageUp` 之类反门，
     正分支才是基线窗），此时「上一组的 guard」既不是这个条件、方向还可能相反。
   - 正确做法：把「若P则」的作用域标记**顺着条件来源显式穿线**（要区分「若P则」产生的条件、
     触发器自带的 guard、取反参数三种形态），不是从上一组反推。
2. **同子句内两个「若…」分支**（pet-3939 贝瑶）：「若A则X，若B则Y」里 B 的条件落成了
   op 级 `if`，而 A 的条件成了**条目级 guard**——条目 guard 会 gate 整条
   （`mechanics/soulmark/index.ts`：`if (!condEval(octx, view.world)) continue`），
   于是 B 的效果被 A 的条件一起收紧。本轮试过补 part 级「若P当回合Y」拆分，
   残文确实 -1，但门是错的（冻伤分支被烧伤门收紧），**已撤回**。
   - 正确的形态：两个「若」分支各自成条（A 的 guard 在 A 条、B 的 guard 在 B 条）。
3. **无触发子句沿用前句 hook 时会连带继承前句的守卫**（同 pet-3939）。

修这一族时，务必用 `scratch/parse-diff.mjs` 逐条核源文本——本轮 219 条里有一半是「看起来对
但其实错」的，只看数量会误判。

## 五、内容包同步的纪律

当前还有 **345 条** `different-effects`（包内条目与当前解析不一致）+ **4 条**包内无条目
（那 4 条是 `NO_MOUNT` 白名单里的有意不挂，见第九轮）。
不能整库回填——回填可能**删效果**或**丢条件**。

**判据（`scratch/drift-buckets.mjs`）**：把每个条目展开成语义签名
`(hook, op 名+参数, 条件集合)`，其中**条件集合把条目 guard 与 op 级 if 合并**——
「条件在 guard 上」与「条件在 op.if 上」两种写法被抹平，而「条件真的没了」仍看得出来。

| 桶（`sync-soulmarks --scan` 口径，第十四轮起为完整有序 IR 比较） | 条数 | 处置 |
|---|---:|---|
| same（逐字相同） | 1890 | — |
| equiv（只差形状） | 0 | 分桶口径改为完整有序 IR 后清零 |
| fewer（当前解析更少，回填=删除） | 110 | **不能批量回填**，见下 |
| differ（读法改写） | 211 | 逐条看（旧口径 151；口径变严后 60 条从 fewer 改判 differ） |
| more（纯新增） | 0 | — |
| missing（包内无条目） | 4 | `NO_MOUNT` 有意不挂 |
| stale（包内有条目但解析无） | 24 | 逐条判 |

**「当前解析更少」这 172 条为什么不能批量回填**（实测）：
回填等于删掉包里的效果。抽样 3 条（pet-4713 / 4736 / 4743）删掉的确实是
「旧解析器丢条件后无条件生成的错效果」（`dmg_immune@nextAlly`、`crit_always@self`、
`shield@opponent`）——回填方向对。但另一部分**包里的内容比解析器还细**：
pet-4417 疾翼先锋的包内条目带 `perHpLostStep`（每损失1%体力加2%伤害），
当前解析器产不出来（10-21 那轮引入的 "nested trigger timing" 隔离把它扣下了；
08e2de6 的解析器还能产出较粗的 `dmg_boost{pct:2}`），而且包内那条有专门的行为测试
（soulmark-content-sync 的「pet-4417 每损失1%只加2%普通攻击伤害，且无流血时不施加」）。
**批量回填会删掉已验收的更细实现**——第九轮实际回填 224 条后该测试立刻失败，已撤回。
这 172 条要先分清「旧内容该删」与「包内比解析器细」两类，前者才可回填。
配套工具：`scratch/parse-at.mjs`（跨版本解析对比）、`scratch/fewer-sample.mjs`（抽样看删掉什么）。

**四个反直觉的坑（都踩过）**：
1. **「守卫数减少」≠ 条件丢失**。pet-4728 就是被这个判据误伤的：条件只是从条目 guard
   挪进了 react 窗（10-21「使用技能时」改造），语义没变。判条件丢不丢，要看
   **条件是否还被应用**（条目 guard / op 级 `if` / react 窗参数）。
2. **「效果条数变多」≠ 纯新增**。pet-4814 是多出 2 条效果的同时丢掉了守卫
   （`weCounterFoe`）——回填等于把带条件的效果改成无条件执行。
   批量回填前必须同时过「守卫损失」与「语义等价」两道检查。
3. **解析器也会回退**。10-21 那轮引入的 "nested trigger timing" 隔离把更早轮次
   已验收的效果扣下了（pet-4417）。包与解析器是**双向**有差距的：包有陈旧的，
   解析器也有退步的。批量回填前先确认「当前解析确实更对」，别默认解析器是唯一真相。




## 六、别踩的坑（本轮实际踩过）

- **规则顺序**：新规则放在同族宽规则之前；`tests/fixtures/effects-rule-order.json`
  只锁**已存 id 的相对顺序**，新 id 不必写进去。
- **触发词尾段可省**要慎重：把通用触发词的尾段放开会让「每次…使用攻击技能在…」这类组尾
  误落成裸触发组（实测 219 条变化、4 条回归）。只给**特定形态**（如「若」形）开口子。
- **条件守卫方向**：条件可能以取反参数存在，从上一组反推作用域会拿到**反号**的守卫
  （pet-4834 的「不处于」被取反成「处于」），效果永不触发却看不出问题。
- **门禁顺序**：`typecheck` 要在测试文件写完之后再跑（本轮有一次门禁跑在测试文件写入之前，
  漏掉了类型错误，提交后才补）。
- **新增触发词必须逐字收窄**（本轮踩过）：为 pet-4587 加「对手攻击时 → onDamaged」时，
  一开始写成了 `对手(?:每次)?(?:使用)?(?:攻击技能|攻击)?时`——**太宽**，
  把「对手**使用攻击技能时**所有pp-2」这类**纯用技反应窗**也抢挂到了 onDamaged，
  一口气改了 6 只（pet-4728 / 4832 / 4875 / 3386 / 3511 / 4368 / 4355），
  触发时机整体前移 = 语义回归。收紧成 `对手(?:每次)?攻击时` 后回归归零。
  同理，body 二次匹配前的 break 条件（`soulmark-parse.mjs` 里挡「对手攻击技能命中自身时」
  的那行）也要同步放行 `攻击(?!时)`，否则新触发词根本走不到。
  **教训**：加触发词 = 同时改「匹配表」和「提前 break 的保护表」，两处都得收窄到同一形态。
- **归一/剥字的顺序比词表更要命**（第六轮连踩三次）：
  1. `.replace(/^若?我方(?=…)/, "若自身")` —— 替换串写死带「若」，原句没有「若」时也被套上，
     整句从「我方攻击必定致命」变成「若自身攻击必定致命」，效果层认不出（pet-3361）。
     改成 `^(若?)我方` → `"$1自身"`。
  2. 「后」残头剥字 `.replace(/(?<!然)后(?=恢复|回复)/, "")` 跑在 **text 级归一链**里，
     抢在 part 级 `PART_PRE_STRIP` 前面，把「出手后恢复」「之后恢复」切成「出手恢复」「之恢复」
     （pet-3463 / pet-3675）。**修法是把它移到 part 级、PART_PRE_STRIP 之后**——
     不能简单改成「前字不是汉字才剥」，因为技能侧的残头「后恢复自身体力250」前面正是汉字
     （实测 pet-2486 回归）。
  3. 同理，任何「X后」「X时」类**完整词形**都必须由 PART_PRE_STRIP 整词剥，
     早于它的零散剥字规则一律是抢跑。
- **句尾括注会改变分句边界**（第十二轮踩过）：「（boss无效）」这类括注不只是标记，
  `splitLocalBossScopes` 会按**时序触发词**把整句切开，让括注只罩住最近的那个时序片段。
  切点落在**条件/分支标记与它的负载之间**时（「未触发则**回合结束时**X」），条件与负载被拆到
  两段 → 条件成孤儿、负载无条件执行。
  **教训**：改分句边界前，先问「这句里的条件/分支标记和它的负载会不会被切开」。
  判据：同一句话加不加句尾括注，**条目集合与残文文本都应当一致**（本轮已写成回归测试）。

## 一之六、分数型附加固伤的概率丢失（第十三轮已修，技能侧仍待做）

「攻击有50%几率附加自身最大体力1/3的固伤」——**该 50% 整段丢失**（该 50% 的变成 100%）。
根因两级：效果层的「孤儿概率前缀回填」名单漏了分数型固伤
（`flatSelfFrac`/`flatFoeFrac`/`flatSelfPct`）；魂印层的 `attachDamage → op` 也没把
`flatChance` 挂到产出的 damage op 上（同族 flatBonus 一直是对的）。

第十三轮已修**魂印侧**（5 只：pet-3457/3487/3574/3639/4291），全库 diff：marks 5 条 / moves 0 条。

**留下的两件事**：

1. **技能侧同款缺口**：引擎的 `flatChance` 只门控 `flatBonus`/`flatRange`，
   **不门控分数型固伤**（`ops/damage-family.ts` 的判定在分数型加项之前）。
   顺带改引擎会波及既有 7 条「flatChance + 分数固伤」条目，其中一部分概率来自
   「未触发则」分支的结转——**要先判清那 7 条的概率归属**，再动引擎。
2. **概率前缀跨子句结转**：「未触发则 + 概率前缀 → 概率挂在 else 负载上」是
   `add-effect-r4c.test.ts` 与 2 条 parser golden 明确编码的**既有验收决策**
   （第十三轮试过改掉，撤回）。第十三轮据此把改动收窄到魂印侧最小修复。
## 一之七、第十四轮：同步分桶口径变严后的 differ 形态分类（下一轮主战场）

外部代理把两个同步工具的「语义等价」判定从**集合签名**（`hook|op(去 if)|条件集合`，
忽略顺序/重复/chance/bossGate/elseOps）改成**完整有序 IR 比较**。
口径变严的直接后果：魂印侧 differ 从 151 涨到 211，fewer 从 171 降到 110
——**60 条原先被误判为「纯减少」的其实是改写**。

用 `node scratch/differ-shapes.mjs`（新增，只读）按「包内旧条目 vs 当前解析新条目」归类：

| 形态 | 条数 | 含义 | 处置 |
|---|---:|---|---|
| 纯减少 | 121 | 包内有、当前解析不产出的条目 | **不可批量回填**（回填=删效果），逐条判是「包里的错效果该删」还是「包里的更细该留」 |
| op 级增删/混合 | 118 | 条目内 op 集合变了 | 逐条看：多是 hook 迁移（react 窗化 / onMoveUsed↔onDamageDealt） |
| 同 hook 改写 | 61 | hook 不变、op 体变了 | 逐条看：多半是条件改写或幅度修正 |
| 纯新增 | 2 | 当前解析多出的条目 | 可回填（纯新增不删东西），但仍要确认语义正确 |

**接手后的第一步**：先做「纯减少 121」——它们是唯一会**删掉现网效果**的一类，
必须逐条拿原文判「包里那条是不是旧解析器的错效果」（可删）还是「包里比解析器细」（不可删）。
