手法（每只都要走完这四步，缺一不可）：
1. `node scratch/soulmark-residue.mjs --ids pet-XXXX` 看残文原句；

## 三、同一机制族的三处未解（下一轮最有价值的一块）

**族：条件作用域与分句归属。** 三处症状，同一个根——「条件属于哪一句」没有显式标记：

1. **「若P则A，且B」**：P 应同时罩 A 与 B；B（且续组）现在拿不到 P → 无条件执行。
   - 本轮两次尝试都被撤回。第一次（续组继承上一组守卫）**219 条变化、样本 8 条里 4 条是错的**
     （pet-4765/4799/4846 串味，pet-4834 语义反转）；第二次（把「且」切分的前半段另起一组）
     触发了「触发成功则…」分支的保护（soulmark-parse.test 的「不误伤并列子句」用例）。
   - 已确认的根因：作用域条件**未必在条目的 guard 里**——条件可能以**取反参数**形式存在
     （`passCondGate` / `negateBaseParam`：条件不成立时给宿主挂 `notSelfStageUp` 之类反门，
     正分支才是基线窗），此时「上一组的 guard」既不是这个条件、方向还可能相反。
   - 正确做法：把「若P则」的作用域标记**顺着条件来源显式穿线**（要区分「若P则」产生的条件、
     触发器自带的 guard、取反参数三种形态），不是从上一组反推。
2. **同子句内两个「若…」分支**（pet-3939 贝瑶）：「若A则X，若B则Y」里 B 的条件落成了
   op 级 `if`，而 A 的条件成了**条目级 guard**——条目 guard 会 gate 整条
   （`mechanics/soulmark/index.ts`：`if (!condEval(octx, view.world)) continue`），
   于是 B 的效果被 A 的条件一起收紧。本轮试过补 part 级「若P当回合Y」拆分，
   残文确实 -1，但门是错的（冻伤分支被烧伤门收紧），**已撤回**。
   - 正确的形态：两个「若」分支各自成条（A 的 guard 在 A 条、B 的 guard 在 B 条）。
3. **无触发子句沿用前句 hook 时会连带继承前句的守卫**（同 pet-3939）。

修这一族时，务必用 `scratch/parse-diff.mjs` 逐条核源文本——本轮 219 条里有一半是「看起来对
但其实错」的，只看数量会误判。

**「当前解析更少」这 240 条为什么不能批量回填**（本轮实测）：
回填等于删掉包里的效果。抽样 3 条（pet-4713 / 4736 / 4743）删掉的确实是
「旧解析器丢条件后无条件生成的错效果」（`dmg_immune@nextAlly`、`crit_always@self`、
`shield@opponent`）——回填方向对。但另一部分**包里的内容比解析器还细**：
pet-4417 疾翼先锋的包内条目带 `perHpLostStep`（每损失1%体力加2%伤害），
当前解析器产不出来（10-21 那轮引入的 "nested trigger timing" 隔离把它扣下了；
08e2de6 的解析器还能产出较粗的 `dmg_boost{pct:2}`），而且包内那条有专门的行为测试
（soulmark-content-sync 的「pet-4417 每损失1%只加2%普通攻击伤害，且无流血时不施加」）。
**批量回填会删掉已验收的更细实现**——本轮实际回填 224 条后该测试立刻失败，已撤回。
这 240 条要先分清「旧内容该删」与「包内比解析器细」两类，前者才可回填。
配套工具：`scratch/parse-at.mjs`（跨版本解析对比）、`scratch/fewer-sample.mjs`（抽样看删掉什么）。

**三个反直觉的坑（都踩过）**：
1. **「守卫数减少」≠ 条件丢失**。pet-4728 就是被这个判据误伤的：条件只是从条目 guard
   挪进了 react 窗（10-21「使用技能时」改造），语义没变。判条件丢不丢，要看
   **条件是否还被应用**（条目 guard / op 级 `if` / react 窗参数）。
2. **「效果条数变多」≠ 纯新增**。pet-4814 是多出 2 条效果的同时丢掉了守卫
   （`weCounterFoe`）——回填等于把带条件的效果改成无条件执行。
   批量回填前必须同时过「守卫损失」与「语义等价」两道检查。
3. **解析器也会回退**。10-21 那轮引入的 "nested trigger timing" 隔离把更早轮次
   已验收的效果扣下了（pet-4417）。包与解析器是**双向**有差距的：包有陈旧的，
   解析器也有退步的。批量回填前先确认「当前解析确实更对」，别默认解析器是唯一真相。




## 六、别踩的坑（本轮实际踩过）

- **规则顺序**：新规则放在同族宽规则之前；`tests/fixtures/effects-rule-order.json`
  只锁**已存 id 的相对顺序**，新 id 不必写进去。
- **触发词尾段可省**要慎重：把通用触发词的尾段放开会让「每次…使用攻击技能在…」这类组尾
  误落成裸触发组（实测 219 条变化、4 条回归）。只给**特定形态**（如「若」形）开口子。
- **条件守卫方向**：条件可能以取反参数存在，从上一组反推作用域会拿到**反号**的守卫
  （pet-4834 的「不处于」被取反成「处于」），效果永不触发却看不出问题。
- **门禁顺序**：`typecheck` 要在测试文件写完之后再跑（本轮有一次门禁跑在测试文件写入之前，
  漏掉了类型错误，提交后才补）。
- **新增触发词必须逐字收窄**（本轮踩过）：为 pet-4587 加「对手攻击时 → onDamaged」时，
  一开始写成了 `对手(?:每次)?(?:使用)?(?:攻击技能|攻击)?时`——**太宽**，
  把「对手**使用攻击技能时**所有pp-2」这类**纯用技反应窗**也抢挂到了 onDamaged，
  一口气改了 6 只（pet-4728 / 4832 / 4875 / 3386 / 3511 / 4368 / 4355），
  触发时机整体前移 = 语义回归。收紧成 `对手(?:每次)?攻击时` 后回归归零。
  同理，body 二次匹配前的 break 条件（`soulmark-parse.mjs` 里挡「对手攻击技能命中自身时」
  的那行）也要同步放行 `攻击(?!时)`，否则新触发词根本走不到。
  **教训**：加触发词 = 同时改「匹配表」和「提前 break 的保护表」，两处都得收窄到同一形态。
- **归一/剥字的顺序比词表更要命**（第六轮连踩三次）：
  1. `.replace(/^若?我方(?=…)/, "若自身")` —— 替换串写死带「若」，原句没有「若」时也被套上，
     整句从「我方攻击必定致命」变成「若自身攻击必定致命」，效果层认不出（pet-3361）。
     改成 `^(若?)我方` → `"$1自身"`。
  2. 「后」残头剥字 `.replace(/(?<!然)后(?=恢复|回复)/, "")` 跑在 **text 级归一链**里，
     抢在 part 级 `PART_PRE_STRIP` 前面，把「出手后恢复」「之后恢复」切成「出手恢复」「之恢复」
     （pet-3463 / pet-3675）。**修法是把它移到 part 级、PART_PRE_STRIP 之后**——
     不能简单改成「前字不是汉字才剥」，因为技能侧的残头「后恢复自身体力250」前面正是汉字
     （实测 pet-2486 回归）。
  3. 同理，任何「X后」「X时」类**完整词形**都必须由 PART_PRE_STRIP 整词剥，
     早于它的零散剥字规则一律是抢跑。
