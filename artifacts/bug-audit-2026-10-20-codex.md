# 项目缺陷检查与修复

日期：2026-10-20。

本轮覆盖规则加载、Host 协议与持久化、服务端生命周期、客户端请求与存档、Agent 决策，以及真实浏览器业务流程。保留上一轮未提交的架构修改，不修改 executable hash 的算法或版本常量。

## 已修复

| 范围 | 复现条件与原问题 | 修复与回归 |
|---|---|---|
| 持久化原子性 | 第二侧提交导致结算后，resolution 写入抛错：数据库已经保存新快照，但缺少结算记录；内存也保留已推进状态，同键重试无法补齐 | 一次 Host 操作用外层事务包住所有写入，内部事务使用嵌套 savepoint；失败回退内存和提交游标。故障注入测试覆盖回滚后原请求重试 |
| 建局与 ACK | 建局初始事件写入失败会留下半条对局；ACK 写入失败仍推进内存游标 | 同样纳入数据库与内存的原子边界 |
| 幂等协议 | 同键、同动作、同 decision 但不同 baseRevision 被当成精确重复 | 重放条件包含 baseRevision；不同有效负载返回幂等冲突 |
| 提交回执 | 收齐提交并打开下一回合后，原决策回执仍报告 resolved=false | 按当前 decisionId 是否仍等于原 decisionId 判断 |
| 只读合法动作 | 已提交、等待对手时 observe 的动作为空，但 ReadOnlyView 仍返回核心动作集 | 直接从权威公开观察投影动作，两个入口一致 |
| 嵌套原子校验 | react/grow 等 payload 的 op 可以绕过顶层 allowlist、feature 和伤害类型限制 | 抽出统一递归验证；技能和魂印装载共用，分组 rider 之前完成检查 |
| 编译输入所有权 | rider 分组改写传入 JSON，冻结调用方的 limits/allowlist；同一原始文档再次编译可能因内部字段而拒载 | 编译入口克隆输入，保留调用方数据和可重复编译行为 |
| 魂印标识 | 先用条目 id 重建 Map，再核对 Map 键与 id，原字典错误的键被掩盖 | 保留原始字典键后核对，拒绝键/id 不一致的内容 |
| 真实规则包 | peak 使用 synthetic-v2，但其中包含命中修正及嵌套 hp_delta；原检查没发现配置不一致 | peak 使用独立 peak-v1，显式声明 accuracy 和 hp_delta；real-v1 补齐已有直损原子的声明。生成工具和客户端规则到包名映射同步更新 |
| 插件路由 | extra 插件晚于静态插件登记，所有请求先被静态 catch-all 截走；错误 HTTP 方法也被吞成 404 | 先匹配具体路由，再走 wildcard；匹配到路径但方法错误返回 405 |
| HTTP 边界 | 动态参数的非法百分号编码抛 URIError，变成 500；读取静态目录抛 EISDIR | 非法 URL 编码返回 400；目录不作为静态文件返回 |
| 服务端资源 | 后续插件装载失败不清理前序资源；listen 错误没有 reject 路径；正常关闭漏关世界数据库 | 启动异常统一清理，监听错误正常 reject，正常关闭与异常关闭都释放插件和两个数据库 |
| 存档隔离 | 自定义数据库名不以 battle.db 结尾时，世界库与战斗库共用路径；所有临时测试服务会读写项目真实 local-team.json | 世界库使用独立文件；队伍文件跟随数据库目录，临时服务各自隔离，CLI 仍使用 data/ 下的持久存档 |
| 客户端轮询 | destroy 后的迟到响应仍回调；重新启动 poll 保留旧定时器；回调失败前提前推进 cursor | 使用轮询代次隔离，撤销旧定时器，丢弃失效响应；回调成功后推进 cursor |
| 请求与提交 | HTTP 错误体被当成成功数据；POST 没有超时；AI 请求失败后永久锁住 decision，人类提交可能产生未处理拒绝 | 统一请求超时与 HTTP 错误处理；失败的 AI 提交释放重试标记，人类提交显示错误 |
| 队伍重置 | reset 先于首次 GET 返回时，迟到的存档覆盖刚完成的重置 | 重置走同一个本地变更入口并标记已修改 |
| LLM 预算 | policy 的调用次数和 usage 跨决策累积，后续决策永久 fallback；成功调用仍残留预算计时器，修复路径残留 abort listener | 预算改为单次决策局部状态；首轮与修复共用可取消请求路径，统一清理 timer/listener |
| LLM 取消 | 预先取消仍发送请求；主动取消误报 timeout；不遵守 signal 的 provider 只能等到超时 | 请求前检查取消；区分 aborted/timeout/parse/provider；决策层独立与取消信号竞速 |
| 时钟与额度 | 系统时间回拨可扩大决策预算；输出超限仅记日志仍接纳提案 | 使用 monotonic 时钟；超额提案 fallback |
| Agent 决策 | 并发 stepAsync 重复调用模型、重复写 transcript；非己方决策也调用模型；构造时传入的 planner 参数未参与计算 | 加入决策进行中集合，检查 actor 和合法动作，两个入口都传递 planner 配置 |

## 验证

- 修复前的完整基线：152 个测试文件、2,244 项通过。随后新增故障注入测试，先复现持久化、协议和轮询缺陷，再修复。
- 最终完整回归：158 个测试文件、2,274 项全部通过，较基线增加 30 项回归测试；最终代码上的运行用时 102.44 秒。
- Playwright：9 条端到端测试全部通过，包括双人对战、正常/跳过动画一致性、慢网络、替补、队伍编辑、背包、页面重入和世界挑战领奖。
- 类型检查、客户端生产构建、内容校验、契约生成一致性、schema 同步、公开/内部边界和 diff 空白检查通过。
- 技能编译：53,697 条，0 失败；魂印编译：1,731 枚、4,016 条运行时条目，0 失败。
- 解析 golden 的 360 条样本一致；覆盖率 ratchet 通过。未重写覆盖率文件或 golden 夹具。

## 规则包变更影响

hash 的计算代码和引擎版本常量未变。peak 从合成测试配置切到独立配置后，按现有算法会有新的规则/内容引用；旧 peak 对局要恢复或重放，仍须保留原版本的规则包和执行产物，当前默认目录不自动充当历史版本归档。已有 synthetic-v1/v2 配置保持原样。
