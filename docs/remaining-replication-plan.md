# 剩余魂印与技能复刻

状态：计划。不改引擎、不改解析器、不改覆盖率基线。
上一份实现记录在 `docs/soulmark-plan.md` 和 `docs/skill-effects.md`。那两份把已经落地的批次写成了「已完成」，读起来像还差一口气。差的不是一口气。

数字以这两份报告为准，不要另起一套分母：

- 技能：`content/claims/_coverage-baseline.json` 与 `content/claims/_effects-coverage.json`，2026-10-04。有文本的技能 53798，整招解析干净 46003（85.5%），半解析 5386，子句 104619/114579（91.3%）。编译失败 0。效果 golden 351 条不动。
- 魂印：`content/claims/_soulmark-coverage.json`，2026-10-03。3526 只精灵里 1884 只有魂印文本。整印无残留 764（40.6%），有条目但仍有残留 862，子句 2791/2896（96.4%）。2026-10-04 的编译门禁是另一件事：已解析出的 1445 印 / 2656 条条目，失败 0（`content/claims/_soulmark-compile-failures.json`）。编译绿不等于文本复刻完。

子句百分比和「这只精灵的魂印做完了」不是同一个数。技能按 `；` `，` 切开，残留条数从子句数里减。魂印一条印记只要 `unparsed` 非空就算没做完，哪怕 96% 的子句已经产出了条目。所以魂印看起来「子句几乎满了、整印只做了四成」。

## 为什么停在这里

不是解析器没写。技能走 `tools/effects-parse.mjs` 加 `tools/effects-rules/`，魂印走 `tools/soulmark-parse.mjs`，效果体进同一套 `applyOp`。能写成现有 op 的句子，前几批已经吃掉了。剩下的每条都至少踩下面一种。

### 1. 句子是孤例，规则一宽就抢别人的

2026-10-04 的未解析清单 `artifacts/unparsed-reasons.json` 比基线旧约 0.2 个百分点（子句 91.1%，整招 45871）。形状仍然有效：10195 条残留里，8504 条的原因是 `no-rule`。没有共同句式，是一万种说法里各出现一两次的尾巴。

一条新规则必须写在同家族宽规则前面（`docs/extension-checklist.md` 第 4 节）。写在后面匹配不到，写得太宽会把已经进 golden 的 351 条改掉。这一档能涨覆盖率，但只能一小条一小条涨，不能再指望一批规则加五个点。

### 2. 原文没有系数，补上就是在编公式

文本只给了名字，没给数。这类已经显式标了 `UNVERIFIED`，不是漏写正则：

- `惩罚`、`对方能力等级越高`、`此技能威力越大`：威力随能力等级变，倍率不在句子里。
- `连续使用时威力提升100%` 里有的有数字，有的只写「会增加威力」。没数字的不能填一个默认倍率。
- `一定几率`：没有百分比。
- 致命一击「几率提升」：没写提升多少。转化率文档里也没有，`stat:"crt"` 现在只记账、不参与伤害。

巅峰包里已经碰过同一类：圣灵谱尼的「光荣之梦」原文有「自身体力低于 1/2 时造成等量固伤」，编译结果只有能力等级、偷能力、回血和先制，没有伤害 op。它是属性招。硬加一条伤害会把这招改成另一招。必中已经能从文本里认出来，但 `content/rulesets/synthetic-v2.json` 没有 `accuracy` 特性，这个规则包里所有招本来就恒中。两条都不要在没核对出处时补。

### 3. 差的是战斗状态，不是句子形状

魂印运行时已经能做的，不要再做一遍：回合开始/结束、登场、受击、击败、换下、使用技能、类别连用（连续使用攻击技能 / 属性技能，`streak`）、`bossGate`、印记三处存放（单位 / 技能槽 / 场地）。`sameMove: true` 也已经在 `packages/battle-core/src/mechanics/soulmark/index.ts` 里结算，合成用例是绿的。解析器没接上：`tools/soulmark-parse.mjs` 把「连续使用」且后面不是「攻击技能 / 属性技能」的整句丢进延期。同一技能、相同类型、每连续使用 1 回合再叠威力，都还在这句负面先行后面。同一技能可以接到已有的 `sameMove`。相同类型和「每回合再加威力」是另一套计数，运行时没有，不要塞进 `streak`。

再往下是引擎里根本没有的域。解析器已经把它们标成延期，而不是假装解析成功：

- 背包 / 场下 / 下只精灵。现在是 1 对 1 加替补，没有「对手背包里体力最高的那只」「场下每受 100 点伤」。
- 有名字的整套机制：处决、致命印记、龙鳞、星皇之怒、神秘结界、形态切换。印记层数本身有了，这些是跨回合、跨背包、还带专有名词的状态机。
- 体力快照（「记录体力，之后回到记录」）、复活检查点、护盾值被打碎之后的第二段、能力上限另算一截、体力上限加减（图鉴种族值里可能已经含了，不能再加一次）。
- 「上述效果」「以上方式」：指代前面好几条，没有稳定的绑定。
- 性别、日历（每月某日）、专属道具数量、契约召唤物。不是这一局战斗的状态。

图鉴原文还经常不是效果句，是攻略站的问答。十二只巅峰精灵全部带 `soulMark.text`，其中十一只以「问：……答：」开头，圣灵谱尼、天启帝君、弑序神罗、至序圣华都是这种。解析器会剥「答：」再切句，剥完仍剩说明文字。整印 40.6% 有一大块是这个，不是钩子没注册。

### 4. 解析完也不会自动出现在现在这局里

`content/peak/pack.json` 的魂印文件指向 `content/synthetic-v2/soulmarks.json`，那是实验室夹具，不是 1884 只的编译结果。巅峰单位自身不写 `soulMark`。所以大厅里这十二只没有真实魂印。技能也是手写的四招加第五，不是图鉴里那十几到二十几招的编译产物。复刻目录和「这局里能打出来」是两步。

## 批次

每批只做一类。门禁不过就停，不把失败写进基线。命令用 `node` 直接跑。结算批不改 `apps/client/**`。不改伤害公式，不改 `hpCapOf`，不手改 `content/claims/_effects-coverage.json`、`_coverage-baseline.json`、`_soulmark-coverage.json`。覆盖率只许由对应脚本重写，而且子句覆盖率不许下降。

### R0 把两份报告重新对齐

魂印覆盖率文件停在 2026-10-03，技能基线是 2026-10-04。先重跑，不改规则：

- `node tools/effects-parse.mjs`
- `node tools/soulmark-parse.mjs`
- `node tools/effects-ratchet.ts`

### R1 技能：编译器丢掉的字段

残留里有一批不是「看不懂」，是规则写出了 `null` 或非整数，门禁删掉后记成 `non-integer/null fields dropped`（`apply_status.turns`、`apply_status.params`、`apply_stat_stage.delta` 这一类）。先修发出这些字段的那条规则，让它要么写出合法整数，要么改成明确的 `unparsedReason`。不要为了过门禁塞一个默认回合数。

过关：`node tools/effects-compile-check.ts` 仍是 0 失败；`node node_modules/vitest/vitest.mjs run tests/battle-core/parser/parser-golden.test.ts`；`node tools/effects-ratchet.ts` 子句覆盖率不低于 91.3。

### R2 技能：反应句被切碎的后半句

`react payload unparsed` 和 `prevApplied payload unparsed` 里有很多后半句本身是旧 op：「对手的防御-1」「100%进入害怕状态」「令对手所有技能降低 2 点 PP」。触发词已经认出来了，后半句没再进规则表，或被切在一个字中间（「必」「使」这种）。

这一批只修切分和「后半句再解析一次」。不新加触发器编号。修完抽 10 条原来失败的原句进 golden，确认整句变成已有的 `react` 加已有 op。

仍失败、而且后半句属于第 2 节「没有系数」或第 3 节「没有这块状态」的，保持 `unparsedReason`，不在这批硬做。

### R3 魂印：只接「连续使用同一技能」

运行时门控已经是 `sameMove === true` 时比较 `prevMoveId` 和本动 id。解析器只放行「连续使用攻击技能」「连续使用属性技能」。

这一批只加：句子明确是同一招（「同一技能」「相同的技能」）时，产出已有的 `sameMove: true`，效果体仍走现有 op。不改 `streak` 的取值。不解析「相同类型」「每连续使用 1 回合威力再加」。那些没有对应计数器。

测试加在 `tests/battle-core/parser/soulmark-parse.test.ts`，用合成句，不改 351 条技能 golden。然后 `node tools/soulmark-compile-check.ts` 仍要 0 失败。

### R4 魂印：差一句就整印失败的那些

整印失败很多是 862 只「已经有条目、还剩一句」。R0 之后按残留条数排序，只挑残留理由属于「这句话用现有钩子和现有 op 写得出来」的。

跳过，并在报告里保持原 reason：

- `party-scope`、场下、下只、背包
- 形态、武道 / 血之道这一类命名状态机
- 处决、致命印记、龙鳞、结界这些专有流程（层数 op 可以继续用，选择背包目标不行）
- 复活、体力记录与回归、护盾打碎后的第二段
- 「上述效果」
- 问答套话剥不干净的说明句。说明句保持未解析，不要为了凑整印把「问：」后面的攻略编成 op

每做完一只，用这只的编译结果打一局固定种子，事件里要出现 `soulmark`。不把 1884 只一股脑塞进巅峰包。

### R5 才接到现在这十二只

R4 里如果圣灵谱尼、天启帝君、光之惩戒·英卡洛斯、瀚宇星皇、艾夏拉、弑序神罗、重生之翼、启灵元神、命运之轮·莫伊莱、帝天战佛、混元天尊、至序圣华里有整印变干净的，再单独开内容批：

### 不做

下面这些留在延期表里，直到有一条带数字、带对象、带时点的出处。没有出处就不做：

- 编造惩罚、按能力等级缩放威力、未写明的暴击转化率
- 组队同时打多个目标
- 用性别、日期、背包道具数量改变战斗
- 为了覆盖率把 `unparsedReason` 改成一个没人读的旗标（`docs/extension-checklist.md` 第 8 节）
- 用 `--update-baseline` 或手改覆盖率 JSON 让百分比变好看
- 重做已经绿的：类别连用、伤害附加段、印记三处存放、魂印编译 0 失败、技能编译 0 失败

做完 R0–R2 之后，技能子句覆盖率会动一点，整招 85.5% 不会接近 100%。做完 R3–R4 之后，魂印整印比例会动，40.6% 那个旧分母如果换过算法，要在报告里另起一行，不能覆盖原数。两边离「图鉴逐字等于页游」都还差第 2 节和第 3 节那两类，那两类不是再加正则能收完的。
