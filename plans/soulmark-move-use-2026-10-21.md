# 使用技能时与命中后的语义分离

日期：2026-10-21。实现由 `gpt-6-luna`、推理强度 `max` 子代理承担；主代理负责计划、review 和独立复核。

## 本轮目标与边界

以上轮 2356 项测试和实时审计的 1032 条已知不完整记录为基线。先完善一个语义家族：明确“使用技能时”的即时效果在 MISS 时也结算，并保持“命中后”的既有成功路径。优先复用已有 `react` 的自身用技触发 11、对手用技触发 3；只有证明现有能力不足时才独立设计新契约。

- hash、引擎版本、IR 版本和已有工作区改动均保留。
- 不修改既有 `onMoveUsed` 的成功命中含义，不把“使用后”“首用”“选择技能”“命中结果”“回合末续发”混入前置用技触发。
- 条件必须在正确时点判断；不能在战斗开始安装窗口时提前消耗源条件或概率。
- 本轮不实现连续物特攻击统一计数、具名状态机或场下选择器。
- 不运行整库生产生成，不覆盖旧审计、官方 claims 或 golden。

## 分阶段交付

1. A、B 独立核对声明、PP、阻断、失效、MISS、命中以及挂起路径，确认最少改动路线；C 提供真实语料与反例。主代理 review 后确定契约。
2. 若已有反应窗口的成长只支持概率而不支持幅度，独立补足已有 `grow` 原子在反应负载中的组合能力。沿用既有累积状态，不为魂印新增幅值字段；旧概率成长保持原语义，两种成长不可静默混用。先通过运行时与装载边界测试，再允许解析器使用。
3. C 逐句实现经过审查的纯使用即时规则，定点同步少量完整精灵 ID；A/B 对新 IR 和实际对局复核。复杂条件、后置时点与关联结果仍保留原句和原因。
4. 冻结实现后统一运行相关与全量门禁，写入日期为 2026-10-21 的新审计和实施报告。无残文数量仍不等于行为认证数量。

## 已审定的组合契约

- 不新增 hook，不修改 engine.ts 的调用时点。react 3 先于 react 11，均在阻断和失效检查之后、命中判定之前。
- 永久窗口安装只做一次；源条款彼此独立，使用 stack:true，避免同键重施加合并负载及覆盖概率。
- react 直接负载首项的 grow(of:magnitude) 使用既有 magnitudeAcc/magnitudeTracks/accTransform，并持久化至既有 params.growAcc；幅度成长在派发前记账。旧 growStep/growCap 仍只增长负载概率，派发后记账，两者混用或多个成长帧必须拒绝。
- 只认证原子负载的致死和恢复行为。现有 react 在挂起时不恢复任意后续负载；本轮不以多段负载假装跨替补续跑。吸取使用单个 hp_delta 的实际扣量回血。
- “使用后”、命中后、首用、连续计数、选择动作和跨时点条件不进入本轮纯使用转换；无法保留条件的语句保留残文。
- Boss 无效等随当前对手变化的门控不能只在 onBattleStart 安装时检查。现有 react 无对应条件通道时，本轮暂缓该源条款，并保留未完成说明；不为覆盖首批样例新增参数。
- 独立复测发现 apply_status 安装/替换 params 时与编译规则包共享引用，首个 transition 写 growAcc 会污染其他对局。另作最小通用修复：状态落地时复制数值参数表，验收同一 FrozenPack 的双对局与源对象不变；不能通过每个测试重编规则包掩盖串扰。

## 验收清单

- 成功命中、数值 accuracy MISS、`hitIf` MISS；自身与对手触发、属性/物理/特殊类别隔离。
- 控制、异常、类别封印、招式失效、无可用 PP 等路径不得提前触发。
- 成长首次数值、封顶、实际扣量吸取；MISS 计一次，阻断不计。
- 致死、替补挂起、JSON 恢复和下一次使用不得重复触发或漏记成长。
- 原“命中后”在 MISS/失效时仍不触发，旧概率成长不变。
- 类型、内容、schema、contracts、架构边界、golden、实时编译以及全量测试通过；hash/版本和官方快照未改。
